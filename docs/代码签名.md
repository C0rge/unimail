# 代码签名

未签名的 Windows 可执行文件会触发 SmartScreen 的「Windows 已保护你的电脑」拦截，
用户必须点「更多信息 → 仍要运行」才能装上。对一个要接管邮箱凭据的程序来说，
这个提示是不该出现的——它训练用户忽略安全警告，而 UniMail 恰恰最需要用户
认真对待凭据安全。

代码签名解决的就是这件事：让二进制与可追溯的发布者绑定。它**不改变功能**。

本文记录「签名链路怎么走」，`build_exe.py --sign` 负责「拿到证书之后怎么签」。

---

## 1. 本仓库已有的能力

| 组件 | 作用 |
|---|---|
| `build_exe.py --sign` | 打包后调用 `signtool` 签名，并**校验结论**；`--sign` 下签名失败即不产出发布物 |
| `tools/self_sign.ps1` | 生成**仅本地可用**的自签名证书，用来验证签名链路本身 |
| `--cert-thumbprint` | 用证书存储里的证书签名（推荐：命令行里不出现密码） |
| `--pfx` + `--pfx-password-env` | 用 PFX 文件签名，密码从环境变量读，避免落进进程列表 |
| `--timestamp-url` / `--no-timestamp` | 时间戳开关。默认打时间戳 |

`build_exe.py` 会自动在 PATH 与 Windows SDK 目录里查找 `signtool.exe`
（随「Windows SDK Signing Tools」安装），并挑版本号最新的一套。

### 为什么一定要时间戳

不加时间戳，签名的有效期就等于**证书**的有效期：证书一过期，之前签的 exe
在验证方看来全部失效，用户会遇到「昨天还能装、今天被拦」。加了时间戳，
签名时间被可信第三方（TSA）固化，证书过期后旧签名依然有效。

因此 `--no-timestamp` 只用于离线自签名测试，**正式发布不要用它**。

## 2. 本地验证（自签名）

自签名证书不被任何其它机器信任，别人下载你的 exe 依旧会看到 SmartScreen 警告。
它的唯一用途是**验证签名链路本身是通的**。

```powershell
# 1) 生成证书（只写入 CurrentUser 存储，不需要管理员权限）
powershell -ExecutionPolicy Bypass -File tools\self_sign.ps1

# 2) 用打印出来的指纹签名
python build_exe.py --sign --cert-thumbprint <THUMBPRINT> --no-timestamp

# 3) 回收：删除证书并解除信任（不留残留）
powershell -ExecutionPolicy Bypass -File tools\self_sign.ps1 -Remove
```

脚本的安全边界（刻意设计）：

- **只操作 `CurrentUser`**，永不触碰 `LocalMachine`，不影响同机其它用户；
- 默认**只创建证书，不修改任何信任关系**。把自签根证书塞进信任库是一个真实的
  安全决定，必须由加 `-Trust` 显式确认，不该由脚本默默替你做了；
- `-Trust` 把证书加入 `CurrentUser\Root` 与 `CurrentUser\TrustedPublisher`，
  使本机 `Get-AuthenticodeSignature` 显示 `Valid`；
- `-Remove` 完整回收上述两处信任项与证书本体。

### 自签名时的预期现象

不加 `-Trust` 时，签名后校验会得到：

| 阶段 | `Get-AuthenticodeSignature.Status` |
|---|---|
| 签名前 | `NotSigned` |
| 签名后（未信任） | `UnknownError`（签名已附加，但证书链不受信任） |
| 签名后（已 `-Trust`） | `Valid` |

`signtool verify /pa /v` 在这种情况下唯一会报的错是
`A certificate chain processed, but terminated in a root certificate which is not trusted`
——**即失败只发生在「信任」环节，签名摘要本身是有效的**。

## 3. 正式签名：证书从哪来

### 3.1 SignPath Foundation（开源项目免费，本项目首选）

面向满足条件的开源项目提供免费的 **OV 级**代码签名服务，私钥存放在 HSM 上，
支持 GitHub Actions 等构建系统、可信时间戳与审批流程。

申请条件（据 <https://www.signpath.org/terms>，核实日期 2026-10-16，以官方页面为准）：

| 条件 | UniMail 现状 |
|---|---|
| OSI 认可的开源许可证 | ✅ MIT |
| 有公开仓库 | ✅ `github.com/C0rge/unimail` |
| 项目处于活跃维护状态 | ✅ |
| 已经发布过要签名的形态 | ✅ v1.0.0–v1.6.1 均有 exe 资产 |
| 不含专有/闭源组件 | ✅ 运行依赖 PySide6(LGPL) / cryptography(Apache-2.0) 均为开源 |
| 不含恶意代码或潜在有害程序 | ✅ |
| 不含「探测/利用漏洞、绕过执行环境安全机制」的功能 | ✅ |
| 遵守隐私与最小权限要求 | ✅ 凭据仅本地加密存储，不上传任何服务器 |
| 提供卸载方式 | ⚠️ 见下方「申请前要补的两件事」 |
| **主页上写明代码签名策略** | ⚠️ 见下方「申请前要补的两件事」 |
| 团队成员在 SignPath 与代码仓库上启用 MFA | ⚠️ 需自行确认 |
| 指定 作者 / 评审者 / 批准者 角色，每次签名请求需批准 | ⚠️ 单人项目也要指定 |

需要注意的两个固有约束：

1. **证书签发给 SignPath Foundation**，因此发布者显示为 SignPath Foundation，
   而不是 C0rge。这是免费方案的代价。
2. **每次发布都需要人工批准**，无法做到完全自动化的无人值守签名。
3. 申请由基金会自行裁量，**不保证通过**。

### 申请前要补的两件事

- **在主页写明代码签名策略**：SignPath 明确要求项目主页有这一节（见
  §4，本仓库已在 `README.md` 中补上）。
- **写明卸载/重置方式**：UniMail 是免安装的便携 exe，没有安装器，
  需要在文档中明确「如何彻底移除本程序与本地数据」（`--reset`）。

### 3.2 商业证书（需自购）

DigiCert / Sectigo / SSL.com 等签发的 OV 或 EV 代码签名证书。EV 证书通常能较快
建立 SmartScreen 信誉，OV 需要一段时间的下载量积累。价格、签发周期与是否需要
硬件令牌差异很大，**需按当前报价自行询价**。

### 3.3 其它可选路径

Azure Trusted Signing 等托管签名服务是近年出现的另一类选择，是否适合本项目
需自行调研其当前资格要求与计费方式——本文不对未核实的信息作断言。

## 4. 接上 CI（以 GitHub Actions 为例）

SignPath 提供 GitHub App 与 Action。典型流程是把「构建」与「签名」拆成两步：
先由 Action 上传待签名的 exe，再由 SignPath 侧审批并签名后回传。

要点（不在此给出完整 workflow，因为提交签名请求需要你本人的
`SIGNPATH_API_TOKEN` 与 `organization-id`，无法代配）：

- 构建产物用 `actions/upload-artifact` 上传；
- 提交签名请求用 `signpath/github-action-submit-signing-request`，
  token 存进仓库 Secrets；
- 用 `signpath/github-action-wait-for-completion`（或等价方式）等待，
  再下载签名后的产物；
- **不要把 PFX 密码或 API token 回显到日志**——这恰好是 `--pfx-password-env`
  存在的理由：密码从环境变量读，不经过命令行。

本地签名（PFX 或证书存储）与 CI 托管签名不冲突：CI 走托管签名更安全
（私钥不落构建机），本地用自签名只做链路验证。

## 5. 本仓库已验证到什么程度

已实测（Windows 10/11 + Windows SDK 10.0.26100.0）：

- `tools/self_sign.ps1` 创建、`-Trust`、`-Remove` 三个路径均可用；
- `build_exe.py` 的签名参数拼装（指纹 / PFX / 关闭时间戳 / 缺少凭据时拒绝）
  有回归测试覆盖，见 `tests/smoke.py` 的「代码签名参数拼装」组；
- 对一个 51 MB 的真实 exe 完成签名：签名前 `NotSigned` → 签名后签名表写入
  （文件增大 1873 字节）、`signtool verify` 能读出签名者证书与文件摘要。

**未验证**：用受信任 CA 证书做的正式签名，以及 SignPath 的托管签名流程——
这两者都需要真实的证书或账号授权，无法在本地代做。
